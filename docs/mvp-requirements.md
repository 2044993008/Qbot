# AI 管家 MVP 需求文档

## 1. 产品定位

AI 管家是一个内置于即时通讯应用的智能助手，通过自然语言交互帮助用户完成聊天辅助、内容创作、信息检索等高频操作。MVP 阶段聚焦**对话交互 + 核心工具调用**，砍掉一切非必要功能。

---

## 2. 核心功能（MVP）

### 2.1 智能对话
- **描述**：基于 LLM 的 ReAct 风格对话，管家具备独立人格（非冷漠机器）
- **核心能力**：
  - 理解用户自然语言意图
  - 识别需要调用工具的场景，自动触发对应功能
  - 简洁、有情感的回复风格
  - 支持根据用户设置的称呼来称呼用户

### 2.2 身份自定义
- **描述**：用户可自定义管家的名字和对用户的称呼
- **功能点**：
  - 设置管家昵称（默认"小Q管家"）
  - 设置管家对用户的专属称呼（如"父王"、"老大"等）
  - 持久化存储，跨会话生效

### 2.3 记忆系统（简化版）
- **描述**：管家能记住用户的重要信息和偏好
- **MVP 范围**：
  - 用户主动要求记住的内容（`write_memory`）
  - 读取已记住的内容（`read_memory`）
  - 按关键词检索记忆（非向量检索，简单文本匹配）
  - 记忆内容持久化存储，按天记录对话摘要
- **砍掉**：向量 Embedding 语义检索、记忆可信度评分、自动事实提取

### 2.4 消息代发（预览确认）
- **描述**：用户让管家帮忙发消息时，先润色再预览，用户确认后才发送
- **流程**：
  1. 用户："给小明发消息说我晚点来"
  2. 管家调用 `polish_text` 润色内容
  3. 管家调用 `send_message(..., preview: true)` 返回预览
  4. 前端展示预览卡片（目标对象、内容、确认/取消按钮）
  5. 用户点击确认后，后端实际执行发送
- **支持**：文字消息、图片消息

### 2.5 文本润色
- **描述**：帮用户把话写得更好听
- **风格选项**：
  - casual：轻松随意（加语气词）
  - cute：可爱风（加颜文字）
  - formal：正式礼貌

### 2.6 聊天记录搜索
- **描述**：帮用户在群聊中搜索历史消息
- **功能点**：
  - 按关键词搜索指定群聊的消息
  - 返回最近 5 条匹配结果（发送者、内容摘要、时间）
  - 支持查看"我自己发过的消息"

### 2.7 QQ 空间动态辅助（纯预览）
- **描述**：帮用户生成/发布空间动态，但 MVP 阶段只给建议和预览，不直接发布
- **功能点**：
  - `suggest_moment`：给用户提供动态文案建议
  - `publish_moment`：返回发布预览（内容、图片），需用户确认后才真正发布
- **砍掉**：编辑动态、删除动态（高危操作，MVP 不做）

### 2.8 AI 生图（预览确认）
- **描述**：用户描述画面，管家生成图片
- **流程**：
  1. 用户："画一只赛博朋克猫咪"
  2. 管家返回预览（含 prompt、风格参数）
  3. 用户确认后调用生图 API（DashScope 万相）
  4. 生成完成后返回图片 URL
- **风格选项**：写实、动漫、卡通、艺术
- **砍掉**：视频生成（当前平台不支持）

### 2.9 定时任务创建
- **描述**：帮用户创建定时提醒或自动任务
- **功能点**：
  - 自然语言解析为 cron 表达式（如"每周一上午8点提醒我上课"）
  - 自动识别任务类型（提醒 / 发消息 / 发动态）
  - 持久化存储到数据库，支持启用/禁用
- **砍掉**：任务执行引擎（MVP 只创建，不自动执行）

---

## 3. 非核心功能（MVP 不做）

| 功能 | 原因 |
|------|------|
| 向量语义检索 | 实现复杂，MVP 用文本匹配替代 |
| 记忆可信度评分 | 非必需，增加认知负担 |
| 自动事实提取 | 容易出错，MVP 只支持用户主动记忆 |
| 视频生成 | 平台暂不支持 |
| 删除好友 / 退群 / 编辑动态 / 删除动态 | 高危操作，MVP 仅返回预览，不实际执行 |
| 表情包匹配 | 非高频需求 |
| Plan-Execute-Observe 复杂编排 | ReAct 已足够处理 MVP 场景 |
| 审计日志后台 | 仅记录错误日志即可 |

## 4. 技术架构（MVP 最小化）

### 4.1 后端
- **框架**：Next.js API Routes
- **LLM**：OpenAI 兼容 API（gpt-4o-mini 或同级）
- **数据库**：Supabase（PostgreSQL）
- **核心表**：
  - `users`：用户信息
  - `conversations`：会话列表
  - `messages`：消息记录
  - `user_settings`：管家配置（身份、记忆）
  - `scheduled_tasks`：定时任务
  - `moments`：空间动态（复用现有表）

### 4.2 前端
- **框架**：Next.js 16 + React 19
- **UI**：shadcn/ui
- **样式**：Tailwind CSS v4

### 4.3 关键 API
| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/bot` | GET | 获取管家配置（名称、身份） |
| `/api/bot` | POST | 发送消息、执行工具 |
| `/api/bot/stream` | POST | 流式对话（可选，MVP 可先不做） |

## 5. 交互设计要点

### 5.1 对话界面
- 管家头像 + 名称展示
- 用户消息靠右，管家消息靠左
- 支持 Markdown 渲染
- 工具调用结果以卡片形式展示

### 5.2 预览确认卡片
当管家执行高危操作时，展示确认卡片：
```
┌─────────────────────────────┐
│  [操作图标] 即将发送消息        │
│  发给：小明                    │
│  内容："不好意思，我今天晚点来~" │
│                             │
│  [取消]        [确认发送]      │
└─────────────────────────────┘
```

### 5.3 记忆展示
- 用户说"记住我喜欢喝奶茶"
- 管家回复"记住了~"
- 记忆内容存入 `user_settings`，不展示在 UI 上

---

## 6. 安全与限制

- **用户级限流**：每分钟最多 30 次请求
- **CSRF 验证**：所有状态变更操作需验证 CSRF Token
- **高危操作强制预览**：发送消息、发动态、生图、删除等必须先预览再确认
- **用户级请求队列**：同一用户串行处理，防止并发冲突

---

## 7. 成功指标

- 用户能顺利完成一次完整的"代发消息"流程
- 用户能让管家记住偏好并在后续对话中体现
- 用户能搜索到历史聊天记录
- 用户能创建定时提醒
